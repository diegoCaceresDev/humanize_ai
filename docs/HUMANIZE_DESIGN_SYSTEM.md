# Humanize Design System

**Status:** Hackathon MVP — approved direction  
**Theme:** Signal violet  
**Product principle:** *Observe the page. Ground the feedback. Keep the human in control.*

This document is the shared visual source of truth for Humanize. Use it for the Chrome extension side panel, the local web demo, PDF reports, and the recording. Do not add new visual styles unless they solve a clear product need.

---

## 1. Brand position

Humanize is a calm, evidence-first UX reviewer. It should feel more like a thoughtful design partner than an autonomous redesign tool.

### Voice

- **Specific:** refer to the heading, CTA, image, or pattern observed.
- **Constructive:** recommend a next step, not a vague critique.
- **Calibrated:** state uncertainty when page evidence is incomplete.
- **Controlled:** describe changes as previews; never imply an irreversible edit.

### Preferred language

- “Three CTAs compete for attention in the hero.”
- “Try making ‘Book a demo’ the primary action and reducing the others to text links.”
- “This is based on the visible viewport and extracted page structure.”

### Avoid

- “This page was generated by AI.”
- “This design is bad.”
- “I fixed your site.”
- Generic praise without evidence.

## 2. Color tokens

### Core palette

| Token | Hex | Role | Use |
| --- | --- | --- | --- |
| `--hz-ink` | `#11131A` | Observer ink | Main dark surface, primary text on light surfaces |
| `--hz-canvas` | `#F8F8F5` | Quiet canvas | Main light report/PDF background |
| `--hz-violet` | `#7357FF` | Action signal | One primary action, selected state, focus elements |
| `--hz-lime` | `#C8F36B` | Evidence lime | Confidence, verified evidence, completed analysis |
| `--hz-coral` | `#FF725E` | Risk coral | High-risk or missing-evidence states only |
| `--hz-mist` | `#E9EBF1` | Structure mist | Light separators and inactive surfaces |
| `--hz-muted` | `#697080` | Quiet text | Supporting labels and secondary explanatory copy |
| `--hz-line` | `#DFE1E7` | Structure line | Borders on light surfaces only |
| `--hz-dark-muted` | `#B8C0CF` | Dark supporting text | Supporting copy inside the extension |

### Semantic states

| State | Signal | Meaning |
| --- | --- | --- |
| Primary action | Violet fill + white text | A user-approved action, such as **Apply focus preview** |
| Evidence / confirmed | Lime marker or text | Source evidence is present or collection completed |
| High priority | Coral only when risk is material | The user should inspect this before publishing |
| Standard finding | Neutral dark surface + text label | A regular opportunity for improvement |
| Secondary action | Transparent surface + thin neutral border | PDF export, revert, dismiss |

### Non-negotiable rules

1. Use **violet only once per visible panel** as the primary action or active state.
2. Do not use lime as a background for long text; it is an evidence accent.
3. Do not use coral for decoration, scores, or ordinary warnings.
4. Do not use gradients, glassmorphism, neon shadows, or rainbow status colors.
5. Pair any status color with a plain-language label; color cannot be the sole signal.

## 3. Typography

Use the system sans-serif stack to keep implementation fast and browser-native:

```css
font-family: Inter, ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif;
```

| Element | Size | Weight | Tracking | Notes |
| --- | ---: | ---: | --- | --- |
| Product name | 15px | 700 | -0.03em | `Humanize` in extension header |
| Page title | 30–36px | 700 | -0.05em | Local demo/marketing only |
| Panel title | 18px | 650–700 | -0.02em | Example: `Priority improvements` |
| Finding title | 14–15px | 650–700 | normal | Direct and scannable |
| Body | 13px | 400 | normal | Minimum readable size in side panel |
| Meta label | 10–11px | 700 | 0.08em | Severity / status only, uppercase |
| Supporting text | 11–12px | 400 | normal | Never essential information only |

Use sentence case. Use title case only for the product name. Avoid decorative fonts and all-caps headings other than compact meta labels.
